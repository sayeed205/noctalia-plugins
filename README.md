# Noctalia plugins

Personal Noctalia plugin development workspace, following the layout and validation
conventions used by the [community plugin source](https://github.com/noctalia-dev/community-plugins).

## Quick start

Install the Luau language server and fetch Noctalia's API definitions into this
repository:

```sh
curl -O https://raw.githubusercontent.com/noctalia-dev/official-plugins/main/noctalia.d.luau
```

Add this checkout as a local plugin source, then enable the starter plugin:

```sh
noctalia msg plugins source add dev path "$PWD"
noctalia msg plugins enable sayeed/hello-world
```

Luau files hot-reload while the manifest is picked up after a Noctalia config
reload. Replace `hello-world/` with a new top-level directory for each plugin.

## Plugin layout

Each plugin directory contains a `plugin.toml`, one or more `.luau` entry files,
`README.md`, `thumbnail.webp`, and `translations/en.json`. Use
[`README_TEMPLATE.md`](README_TEMPLATE.md) for plugin documentation. Plugin ids
use the form `<author>/<plugin>` and the directory must match the part after `/`.

The committed `.vscode/settings.json` and `.zed/settings.json` configure
luau-lsp to use the locally fetched `noctalia.d.luau`. `.luaurc` matches
Noctalia's nonstrict Luau mode.

## Validation

Run the same manifest checks used by CI:

```sh
python3 .github/workflows/scripts/validate-plugins.py
python3 -m unittest discover -s .github/workflows/scripts -p 'test_*.py'
```

`catalog.toml` is intentionally not part of this development repository; it is
generated by the public registry when plugins are published there.
